# Implementation report

Date: 2026-10-02. This report covers brief §19 ("what works, what was tested,
what remains unsupported, and any deviations"). Section numbers (§) refer to
[piano-practice-app-requirements.md](../piano-practice-app-requirements.md).

## Summary

Piano Steps is a working static web app. It turns MusicXML or MXL scores into
two rows of key-name instructions (RH above LH), using the brief's five-symbol
action notation. It also provides:

- a large labelled keyboard and browser piano sound on one shared clock;
- three practice modes (Listen, Steady steps, Follow me with a MIDI piano),
  plus manual stepping;
- a browsable built-in library with honest difficulty provenance;
- local MusicXML import.

It is ready to deploy to GitHub Pages but **has not been deployed**, because no
repository exists yet. See the README for the exact steps.

**Final verification:** 1,298 automated tests pass and the TypeScript
strict typecheck is clean. The production build (`npm run build`) succeeds,
and a GitHub-Pages-style subpath was served and checked.

## How it was built

- **Reference material.** MuseTrainer's source and library were inspected and
  used as reference: its feature set, its Salamander samples and its 69-file
  library. Its Angular/Ionic/OpenSheetMusicDisplay code was **not** reused (see
  Deviations).
- **Contracts first.** Shared types and module contracts were written before
  any code: `docs/ARCHITECTURE.md`, `docs/APP_CONTRACTS.md` and
  `docs/UI_SPEC.md`. Modules were then built in parallel against them, each
  with its own tests, and integrated end to end on the fixtures and the whole
  library.
- **Adversarial review.** Three review rounds each covered six dimensions:
  - musical correctness;
  - engine and timing;
  - Follow me and MIDI;
  - UI and accessibility;
  - import safety, storage and deployment;
  - requirements traceability.

  Every reported defect was independently re-checked, by reproduction where
  possible, before it was fixed. The rounds confirmed and fixed 32, 29 and 26
  defects, and each fix has a regression test. The logs are in `docs/dev/`.
- **Difficulty research.** It was done once, while preparing the catalog, from
  public web information only. Every claimed label went through a separate
  verification pass. The raw research and verdicts are in
  `docs/dev/difficulty-research-raw.json`.

### Not tested

- **Physical MIDI hardware.** No digital piano was connected; all Follow me
  and MIDI behaviour was exercised with simulated events only.
- **Listening.** Audio output was verified by sample loading and scheduling
  tests, not by ear.
- **Other browsers.** Firefox, Safari and Edge were not opened. Safari has no
  Web MIDI; non-MIDI features use standard APIs only.
- **Phone-sized windows.** Only a basic overflow check was done (desktop is
  the target, §16).
- **A live GitHub Pages deployment.** It was not possible without a
  repository.

## What remains unsupported or approximate

These are shown to the user, as plain-language notes and "Needs review"
reasons on cards and in "About this arrangement". They are not silently
flattened.

- **Ornaments.** Trills, mordents and turns play the main note only, and the
  piece is marked "Needs review". Ornaments the file writes out with hidden
  notes are played as written.
- **Grace notes.** They are played as short notes taken from the start of the
  main note. This is an approximation and is noted.
- **Rolled chords** (arpeggio signs) play as block chords.
- **Glissando and slide** marks only sound their two end notes, with a warning.
- **Pedal markings** are not turned into held keys; only written note lengths
  are used.
- **Cross-staff notes.** They are assigned to the hand of the musical line
  (voice) they belong to, and the piece is marked "Needs review" with the
  measures listed. One built-in file (a Gymnopédie copy that reuses voice
  numbers) has a verified per-voice override. With it, that file has the same
  notes as the other edition and is listed as a duplicate.
- **Hand spans** wider than 16 semitones at one moment are flagged for review.
  They may be real stretches or a hand-assignment issue.
- **Octave-shift text** written as words (e.g. "Repeat 8va" in The
  Entertainer) is not applied. A note says the notes play as written.
- **Notes outside A0–C8** are kept, not clamped. The piece is marked for
  review, and Follow me does not wait for keys an 88-key piano lacks.
- **Strict hold/release checking** in Follow me is not implemented; it was
  optional later work (§8). Follow me checks new presses only, and says so on
  screen.
- **Timing under load.** In a background tab, or when the main thread is very
  busy, MIDI-output notes can be late. Browser timers are throttled and the
  lookahead is short to keep Stop responsive. Browser audio uses a longer
  lookahead.
- **Latency.** The marker and keyboard follow the AudioContext clock without
  compensating for output latency, so they can lead the sound by a few tens of
  milliseconds on some systems.
- **MIDI output in Follow me.** With "Play through connected piano" on, Follow
  me still sends "all notes off" and "sustain off" to the piano at loop
  restarts and pauses, even though it played nothing. This could cut a chord
  the learner is holding with the pedal on the same piano. The output is off
  by default.
- **MIDI port auto-pick.** A lone virtual MIDI port (macOS IAC bus or
  loopMIDI) can be auto-selected on a piece never practised before. "Midi
  Through" ports are always ignored, and a remembered piano is never replaced
  by another port.
- **Import formats.** MIDI-file import, scanned or PDF scores and other
  formats are out of scope (§20).

## Deviations from the brief

1. **MuseTrainer was used as a reference, not as a codebase.**
   - The brief says to "reuse MuseTrainer as the starting point where
     practical" (§3).
   - Its archived source is an unmaintained Angular 15 / Ionic / Capacitor app
     with Sentry, in-app purchases, native iOS plugins, and a sheet-music
     cursor (OpenSheetMusicDisplay) at the centre of its timing logic.
   - The brief replaces the sheet music entirely and warns against inheriting
     cursor-based timing bugs.
   - So the app was written fresh as a small Vite + React + TypeScript static
     site, with an exact-tick musical model.
   - Reused from MuseTrainer: its feature ideas (measure range, loop, speed,
     MIDI practice, library), its Salamander piano samples, and its 69-file
     library. Its MIT notice is kept in `THIRD_PARTY_NOTICES.md`.
2. **No heuristic difficulty estimates, and no difficulty for imports.** You
   asked to tag the 69 built-in files from public information only, and to
   leave imported files untagged. The "Estimated" category from §14 is
   therefore not used.
3. **Labels from a file name only are Unrated.** Where "easy" appeared only in
   a file or upload name, not in the score or a published listing, the piece is
   Unrated, following §3's warning that such names are hints. Labels printed
   in the score itself (e.g. "Easy variation", "Intermediate") are shown as
   "per score".
4. **Default tempo.** When a file has no tempo, 120 quarter notes per minute is
   used (MuseScore's default) and labelled as chosen by the app (§8). The
   same default plays an unmarked opening when the file's first tempo mark
   comes later than the first measure (or the first full measure after a
   pickup), with an info note naming that measure (Prelude No. 2: 120 until
   the Presto at measure 28).
5. **Content duplicates are left out.** The rule is the same notes at ≥ 98%
   similarity, never title matching. The reason is listed in the inventory.

## Decisions taken on your behalf

- **The app is called "Piano Steps".** The brief has no name.
- **Keyboard colours.** Physically pressed keys show a dark dot. Wrong keys
  show an amber dashed outline and ✕, never red, so they aren't confused with
  "add".
- **Step preview.** "Next/Previous step" briefly plays the new step's keys
  (0.5 s) when Sound is on. Clicking a column is silent.
- **Library sort order.** By difficulty, then title. Pieces needing review are
  shown by default, with a filter to hide them.

## Licensing status of the built-in scores

The source library calls itself public domain but has no license file. Many
files are modern arrangements by named arrangers, and several carry conflicting
rights text. The *Ode to Joy (Easy variation)* arrangement by Torby Brand was
removed from MuseScore after a copyright claim by MyMusic5.

Every file's rights text and caveat is listed in
[CATALOG_REPORT.md](CATALOG_REPORT.md). Before publishing the site publicly,
decide which arrangements to keep (README → "Removing a built-in piece").
